# 为什么是这几个模块（问题 → 模块 → 依据）

证据分两类：**项目会话证据**来自作者两部剧的工作会话与决策记录，不公开；**公开依据**是创作者访谈、公开稿件和产品文档，链接、定位与证据类型见 `sources.md`。标"作者本地"的资料只在作者机器上，不随仓库分发，别人无法据此复核；核心方法要能只靠公开依据看懂。

| 模块 | 针对的问题（项目会话证据，不公开） | 职业做法（公开依据，或标"作者本地"） | 实证研究的对应（有 / 无） |
|---|---|---|---|
| 台账（伏笔、人物当前状态、信息分布） | 主线是隐喻，没有运转对象；五颗雷无人管；"账一直没摆上桌"在第 11 轮才被说出 | 编剧室先 break story：人物此刻在哪、要什么、怕什么，再排节拍（作者本地：`_skill-dev/film-story/02_一手案例分析.md`） | 分阶段、大纲先行对长程一致性有帮助（Re3、DOC、Dramatron 的人工评估；作者本地：`03_AI协同写作证据.md`）；"台账"这种形式本身未被单独验证 |
| 处境卡 | AI 先写整场、第 11 轮才读圣经；用户要求与已定规则相冲没被指出 | 任何一场戏先回答它在整片里的作用、人物此刻的处境 | 无直接实证；属设计推断 |
| 方向卡 + 实质差异检查 | 9 个方向"不沾边"；换地点冒充新方向。0.6.0 起：只从伏笔推方向，候选一再回到老线索、关系起点与终点相同——所以允许新的核心事件，并给每个候选写关系起点 → 终点 | 编剧室比较的是选择与后果不同的版本；在固定条件下推演困境（绝命毒师） | 多候选若只是表面变体会同质化（Doshi & Hauser 2024；Padmakumar & He 2024）；差异检查是对此的设计回应 |
| 节拍单 + 两次否决回上层 | "叙事感不对、心理状态不对"在措辞层改不好；一天 12 版（10-16） | 大纲阶段改便宜，剧本阶段改贵 | 无直接实证；来自返工记录 |
| 本剧规则表 + 批注依据 + 规则成文 | 本剧规则散在台账、约束文件和十余条记忆里，项目里查不全；理念被当禁令执行（把"表情要有变化"做成一对一删"笑"）；人物的个人习惯被当成约束故事的规则 | 剧集靠成文规则跨集统一，规则多在首批集数后成文、写成目的而非禁令；审稿者按本剧规则而非通用审美判断（The Crown、Mindhunter、Breaking Bad、英国 lead director 交接；作者本地：`Film/research/research_notes/欧美导演工作方法与工具/review_practice_documents.md` §4–§5） | 无直接实证；来自制作实务资料与作者会话 |
| 版本栏 + 本版改动 + 批注块随版本迁移 + 备选台词 | 批注不标版本，改版后旧批注原样留着，看不出哪些还有效；改了哪几句要用户自己比对（10-23） | 职业剧本工具把注释锚定在版本 + 场号 + 台词行上并随修订迁移（Scriptation），修订有页眉、修订标记和备选台词（Final Draft）；产品文档见 `sources.md`"工具"（作者本地的整理：`review_practice_documents.md` §6） | 无直接实证；来自制作实务资料与 10-23 对批注文件的检查 |
| 场次表 + 一次一场 | 节拍改定后一轮写完整集的场（10-22）；用户逐场逐句改，前一场改出来的语气、措辞、人物状态决定下一场怎么写 | 未调研 | 无直接实证；来自 10-22 会话与用户历次逐场批注 |
| 对白三测 + 脚本 | 四种固定失误反复出现 | 职业作者的对白：回应延迟、偏移、落在动作上（作者本地：`02_一手案例分析.md` B 节） | LLM 文风特征有分类与频率（Chakrabarty 等 2024 LAMP）；程序只能查结构线索，艺术判断靠人 |
| 写一场的四步 + 按故障选修改幅度 + 前后对照（0.6.0，`scene-work.md`） | 改稿都在措辞层改，用户看不出修到了哪里（10-23）；0.5.0 的口语测试写的是"删"，脚本又把 "I said I would." 标成复述前情、"Everybody says that." 标成格言式开头（10-24 审阅），照着改会删掉有效的台词 | 保留信息、重写接收与决定（聚焦）；改时机与听众（大鱼）；后场倒查前场（第一头牛）；进入依据（Get Out）；写场办法（John August） | 无直接实证；属设计推断 |
| 从交往写对白 + 声线依据 + 不要误删的写法（0.6.0，`dialogue.md`、`dialogue-patterns.md`） | 台词只会避开失误，被批"太普通、没魅力"，碰不到两人之间的事（10-23）。只压四种失误会把台词压平，这修正了原设计里"对白问题轻量检查压住即可"的判断（作者本地：`_skill-dev/film-story/00_核心判断.md` §3） | 交替代入双方（海边的曼彻斯特）；听者有自己的表达（Sideways）；声音来自办事的方式（Fargo）；长段对白在行动（社交网络）；Scriptnotes 609、438 | 无直接实证 |
| 讨论落稿、困境推演、前后场依赖、观众知情、生活研究（0.6.0，`story-development.md`） | 没有单独的失误记录；讨论记录、零散意见是常见入口，0.5.0 没有对应的做法，讨论过的内容可能被当成已定 | 临时卡与正式卡（风骚律师）；固定条件下推演（绝命毒师）；倒查前场（第一头牛）；悬念与困惑（Scriptnotes 632）；研究提取说话完成的事（Fargo） | 无直接实证；属设计推断 |
| 脚本只读正文、支持中文、分画内 / 画外、制作参数进项目配置（0.6.0，`scripts/`） | 0.5.0 在 78 个带正文标记的场景稿上的实际输出（10-24 审阅）：正文后的批注被当成新的一场；全中文的场没有任何输出；电话里的声音算进同框；4 词/秒、30 s 和人名豁免写死在通用脚本里；"每句都精准接上一句"实际只看问号和词语重合 | 不适用（工具行为） | 不适用；`tests/` 的回归用例覆盖这些情况 |
| 交付写法 + 批注分组 + 改动记录一版一行（0.7.0，SKILL.md §1、§4，`templates/`） | 交付写成散文：同一场的批注散在几块，一条里混着判断、给导演层的要求和给后场的提醒；版本说明一版一段放在核心故事前面（10-25："目前的散文式有点不好理解和阅读"） | 修订按版次记录（Final Draft 的修订页眉、修订标记）；批注锚定原句、随修订迁移（Scriptation）；见 `sources.md`"工具" | 无直接实证；来自 10-25 对批注文件、节拍单的检查 |
| 故事框架卡（0.8.0 迭代 1，`story-framework.md`） | 两部剧的季卡"季终落点"长期待定；处境卡每集从零推；一次下一集构思里三个候选用户都说"没抓住"，随后要求"先思考骨架"（10-30）——季与集之间没有推导层 | 编剧室先定季末落点与调性终点、拆季时才找手段（Armstrong、Hacks）；每季从"人物现在在哪"问起（Breaking Bad 编剧室）；主题写成可争论的中心论点、结构是它的症状（Mazin，Scriptnotes 403） | 无直接实证；来自 10-30 的方向卡返工记录 |
| 戏化字段：三问 / 转向 / 变化轴（0.8.0 迭代 2，`dramatization.md`） | 节拍单有目标、行动、反应等字段，但事件链对了场仍"叙事感不对"：人物在交换信息、场末和开场没有不同；代价的拍被 hold 后没有人提醒下一集要先收代价（EP06 节拍 8、9 hold → EP08 处境卡才发现"那一晚的代价一个都还没回来"） | 三问闸门（Mamet）；意图与障碍（Sorkin）；场要转一个价值（McKee）；变化三轴（Mazin）；谁必须看见由信息分布定（断背山） | 无直接实证；来自 10-30 对两部剧节拍单的回填复核 |
| 对白生成法 + 结构信号 + 脚本新线索（0.8.0 迭代 3，`dialogue.md` §2、§8–10，`dialogue-patterns.md` §5） | 四失误和三测只会避错，台词仍被判"太像台词""请不要使用金句"（10-15、10-29）、"全都是短语，不像人在说话"（10-19）；脚本对中文"像写的"只认"不是……而是……" | 意图与障碍（Sorkin）、说话是为了争取（Mamet）、像写的就重写（Leonard）、不情愿的回应延迟而带理由（会话分析）、回应落在动作与第三人（Normal People） | 无直接实证；结构信号的命中率靠 §8 的删除条件检验 |
| 题材手册（0.8.0 迭代 4，`genre-playbooks/`） | 三部剧题材不同（名利场双人剧、奇幻轻喜剧、校园体育群像），本剧规则各自从零积累；同一类纠正在两部剧里各出现一次才被写成规则（"不对对方说彼此都知道的事""反应早于触发""隔着人群喊人"）；通用默认按正剧口味审轻喜剧 | 编剧按题材先问不同的问题：关系剧问谁替谁做了决定（Hacks）、什么有条件什么拿不走（Succession）；喜剧找场景的游戏（UCB）、限制比能力有趣（Sanderson）；赛制戏人物大于比赛（Friday Night Lights） | 无直接实证；手册的命中率靠 §8 的删除条件检验 |
| 探索 / 采用状态 | 《Negative》段写进三份 Prompt 后整段删 | 剧本锁定前不进制作 | 无需实证；流程纪律 |
