# 术语表（交付里统一用左列；项目旧文件里的旧称照读）

适用于处境卡、方向卡、节拍单、场次表、批注、改稿单、决策记录。剧本正文的台词与动作描写不适用，照 SKILL.md §4 写成人话。

| 术语 | 含义 | 旧称（旧文件里可能出现） |
|---|---|---|
| 交付写法 | SKILL.md §1 的写法：结论先行；一条一事；上下文只给必需的那一点；一处一写，别处留指针；写明状态；改动记录一版一行 | 交付文字（0.3.0–0.6.0 的段名） |
| 台账 | 正典事实、信息分布、伏笔、人物当前状态与时间线的总表（`story/ledger.md`） | 账本 |
| 季卡 | 台账首节：一句话梗概、本季核心戏剧问题、调性边界、季终落点、主角核心利害、不可变更的设定 | — |
| 调性边界 | 本剧不是什么样的故事 | 调性终点 |
| 季终落点 | 本季最后落下的事件或画面 | 季末那一下 |
| 核心利害 | 主角当前必须守住、一旦失去就会改变其选择的东西 | 此刻必须保护的东西 |
| 伏笔 | 已埋设、尚未回收的事件、承诺、把柄或人物间的亏欠；每条注明可引出的选择与最晚回收点 | 债、未兑现的设定 |
| 回收 | 伏笔在后续剧情中兑现、被处理或作废 | 还债、用掉 |
| 信息分布 / 信息差 | 某一事实各人物与观众是否知情：知情 / 不知情 / 部分知情 | 谁知道什么、知一半 |
| 人物当前状态 | 当前目标、恐惧、筹码、上集遗留、下一次交集；写处境，不写性格 | 人物此刻 |
| 目标 | 人物在本拍想得到的 | 此刻要什么 |
| 行动 / 对方反应 | 本拍人物做了什么 / 对方如何回应 | 做了什么 / 对方怎么接 |
| 处境变化 | 本拍之后谁的处境、筹码或关系变了 | 谁的条件变了 |
| 观众知情 | 观众此时已知、未知的信息（与人物的信息差） | 观众此刻知道 / 不知道 |
| 拍间关系 | 方向卡事件链里本拍与上一拍的连接：**因果**（由上一拍直接导致）/ **转折**（上一拍的结果被阻断或逆转） | 连接词、因此 / 但是 |
| 因果链 | 节拍单的一节：本集的事排成编号的几步，每一步引出下一步（所以 / 但是），不靠巧合；只能读成"然后"的地方是断点 | 节拍表的拍间关系一栏 |
| 谁知道什么 | 节拍单的一节：每场之后各人知道的事；人物只知道他看见的和被告知的 | 节拍表的观众知情一栏 |
| 留给下一集的 | 由本集产生、留给下一集的一件具体的事（不另起新谜题）；写在因果链最后一步和"谁知道什么"下面 | 结尾钩子、牵引、单集四问 |
| 核心待决问题 | 处境卡交给用户拍板的那一项 | 真正要定的一件事 |
| 节拍单（Beat Outline） | 定故事往哪走、因果成不成立的一层，一集一份：一句话、因果链、谁知道什么、场次与节拍、对照检查；不写定稿的台词和调度 | 分场节拍大纲 |
| 剧本（Screenplay） | 把节拍单写成观众实际看到和听到的内容，一集一个文件：头部 + 正文（标准剧本格式的 Markdown，`screenplay-format.md`） | 整集稿 |
| 初稿（First Draft） | 按节拍单把每场写出来的第一版；解决有没有，不润色 | — |
| 重写（Rewrite） | 改发生了什么：情节、动机、人物之间的关系；改完节拍单要跟着改（`scene-work.md` §3–§6） | 改稿 |
| 精修（Script Polish） | 结构定了以后由用户发起的最后一轮：先交精修简报，确认后做一轮，只动对白、动作描写和留白，改完节拍单不用动（`polish.md`） | 润色 |
| 阶段 · 状态 | 状态的统一写法：概念 · 讨论中 / 方向已定；节拍单 · 草稿 / 已改定；初稿 · 写到 S__ / 写完；重写 · 进行中 / 结构已锁；精修 · 进行中 / 已采用 | 探索稿 vN / 采用 vN |
| 结构已锁 / 已采用（锁稿） | 两个要用户点头的关口：用户说结构定了，才能精修；用户审过精修后的稿，就是锁稿（Script Lock），才能交导演层 | — |
| 探索稿 | "精修 · 已采用"之前的稿，不管在哪个阶段；不更新正典、不进生产 | — |
| 精修简报（Polish Brief） | 精修动稿之前交用户确认的一份：这一轮的一条原则、仍然有效的要求、锁定的台词、人物声音、逐场、这一轮取代了什么、结构已锁、验收；做完在上面补结果（`templates/polish-brief.md`） | 精修单 |
| 锁定的台词 | 用户定过、精修里一个字不能动的句子；在简报里逐字列出，比稿脚本核对 | — |
| 局部重写 | 用户点名在精修这一轮里重写的某一场的局部；在简报"逐场"里登记，写明要让观众明白什么、保留什么、不许什么 | — |
| 呼吸感 | 台词里的活气：来自手上的事的反应、来晚或没来的回答、对方已经懂了的半句话、只是舒服的沉默；不是添台词、填充词或加停顿（`polish.md` §5） | 喘气的地方 |
| 比稿 | `compare_drafts.py`：两版剧本的结构（场、场景标题、每场的说话人）有没有变，改了哪些句子；带上精修简报时核对锁定的台词；`--dialogue-only` 核对两个语言版本的对白 | — |
| 场景稿 | 剧本里的一场：两个场标记之间的那一段；一次写一场 | 一场一个文件 |
| 场标记 | 剧本正文里每场开头的注释行 `<!-- S03 · 名字 -->`；脚本靠它分场、合计、取出单场 | — |
| 场次表 | 节拍单"场次与节拍"一节开头的总表，一场一行：类型、时长、本场改变了什么、状态；随节拍单改定 | — |
| 拍 / 试写台词 / 作者注 | 节拍单每场一节里编号的条目：谁做了什么、对方怎么回应；拍下面用引用块挂的台词是试写，不算定稿；斜体括注写人物为什么这么做 | 节拍表、关键拍的成立条件 |
| [CANON] 标记 | 节拍单里要用户定的正典事实：原处标 **[CANON: 问题]**，写明暂按什么假设，文末汇总；采用后进台账 | 新事实提案 |
| 对照检查 | 节拍单交付前的自查：因果、动机、片段、回响、知情、本剧规则的偏离，各一句；不成立的在节拍单改（`story-development.md` §6） | 大纲检查 |
| 片段 | 不推主线的场各带来什么；两场带来同一样东西就并掉或换掉一场 | 太散、独立小片段太多 |
| 回响 | 结尾的情感落点靠前面哪几场攒起来；不等于回扣（重复前面的动作或台词） | — |
| 本剧规则表 | 这部剧自己的写法规则（`story/rules.md`）：规则、目的、层级、出处、例子、已登记的例外、状态；写或审一场之前先读 | 已定规则、硬约束、记忆里的偏好 |
| 通用默认 | 本 skill 的三测、脚本阈值、四种对白失误、按故障改稿表与"成立"表；本剧规则另有规定或这场处境需要时让位 | — |
| 违反规则 / 已登记的例外 / 规则之外 | 判断的三类：违反要改或写理由请用户登记；已登记的例外照写；规则没管到的新写法不算问题 | — |
| 规则成文 | 一集采用后，把"这部剧该怎么写"的纠正起草成规则条目，交用户确认 | — |
| 本场改变了什么 | 场次表的一栏：本场造成的变化（信息、关系或情绪从哪到哪）；删去本场，观众会缺失的东西；和别的场不重复 | 一场一个文件时的头部键 |
| 版本栏 | 剧本头部首行：版本号、日期、依据的节拍单版本（对应修订页眉） | — |
| 本版改动 | 剧本头部里相对上一版的改动：改 / 删 / 加，前面标场号，引用旧句与新句（对应修订标记、Track Changes） | 改动清单 |
| 历次 | 剧本头部本版改动之后的一节：更早的版本一版一行，全文在版本历史 | 头部逐版写的版本说明 |
| 这一版改了什么 | 节拍单改版时开头的一节，一条意见一行：哪一场、改成了什么、原话一句；不写上一版，不重引台词；只写现行版 | — |
| 改动记录 / 版本记录 | 记版本变化的地方，一版一行：vN · 日期 · 改了什么 · "原话一句"。节拍单在文末"版本记录"，剧本在头部"历次"，规则表在文末"修改记录"，skill 在 CHANGELOG | 版本说明段落 |
| 指针 | 已写在别处、或被新版本取代的内容只留一行：标题——已被 vN 取代 / 见某文件某节；全文在版本历史（git） | — |
| 批注文件 | 剧本文件旁边每集一个的文件（文件名加 `-notes`），按场分节放批注块，现行块在前 | 附在稿后的批注 |
| 批注块 | 以"场 NN vN · 批注（日期）"为标题的批注：块头写上一版批注的已改 / 沿用 / 作废、结论、脚本线索，条目按处理方式分组（对应 Scriptation 的跨版本批注） | 批注表 |
| 批注分组 | 批注条目按处理方式归组：要改 / 可换 / 待你定 / 保留项 / 交导演层 / 后场衔接 / 已关闭；只写用得上的组 | 逐句罗列 |
| 备选台词 | 挂在批注原句下的几种说法，用户选定后只把一句写进正文（对应 Final Draft 的 alternates） | — |
| 锁定场号 | 场次表确认后不重编；插入的场加字母（S02b），删掉或 hold 的场号不复用 | — |
| 讨论落稿 | 把讨论记录、构思或零散意见分成已决定 / 备选 / 未决 / 待核实，每条带原话（`story-development.md` §1） | — |
| 关系与处境（起点 → 终点） | 方向卡每个候选的一行：这条线让两人的关系与处境从哪里到哪里 | — |
| 误信 / 在等的答案 | 观众知情的两种状态：相信了一件不实的事；此刻在等哪个问题的答案 | — |
| 最小补写 | 后场转折缺前场铺垫时，补在哪一场、最少建立什么，补写在那一场本身也有作用 | — |
| 本场任务 / 人物的当下尝试 | 写一场之前的两行：作者要这场完成什么；每个在场的人此刻想办成什么。两者分开写 | — |
| 进入依据 | 人物为什么来、为什么现在开口、为什么没走或没拒绝；落在前置事件、事务、关系或限制上 | — |
| 交往 / 接收 | 一次开口或举动，以及对方实际接收到的（可能听错、只抓住一个词、不回应） | — |
| 交替代入 | 写一轮交流时轮流站到说的人和听的人的位置，写出回应，再面对这个新事实往下写 | — |
| 修改幅度 | 按故障选改到哪一层：措辞 / 交往方式 / 场内事件 / 前场（`scene-work.md` §3） | — |
| 本轮目标 | 一次改稿要解决的主要问题，一句话；写在本版改动的标题里 | — |
| 前后对照 | 改稿后每处一行：断在哪 → 新稿哪一句或动作补上；另起一行写损失 | — |
| 停止条件 | 关键反应有依据、已定的作用在正文里看得见、结尾和保留项成立 | — |
| 保留项 | 上一版里承载识别性、回应关系或吸引力，改稿时不能丢的台词与动作 | 保留清单 |
| 声线依据 | 台账可选的 G 节：人物对谁、在什么处境、用过哪句已采用台词、观察到的做法；暂定或已确认 | — |
| 外部反馈 | 真实读稿、排练、导演现场或成片带回的观察；记来源和位置，没发生的不虚构 | — |
| 表面线索 | 脚本按问号、词语重合、关键词给出的提示，不是判断 | 精准接话、疑似金句 |
| 画内 / 画外说话人 | 画外：角色名或括注写了电话里、画外、旁白、V.O. 等的说话人。同框人数看动作描写，不按说话人数算 | — |
| 场景标题 | 正文里的二级标题：`## INT. / EXT. 地点 - 时间`（slugline）；一场可以有几个 | 场 NN · 内 · 地点 · 日 |
| 场号 | 节拍单和场标记里的 `S03`（中文稿也可写"场 03"）；场次表确认后不重编 | — |
| 场内小标题 | 正文里的三级标题：同一场里换到另一处，时间不断 | — |
| 动作描写 | 观众看得见、听得见的；一段一个画面，不写心理和机位 | — |
| 留白 | 没有台词、有事发生的一段（一个动作做完、一次不回答、一个声音）；单独成段 | 停顿、呼吸感 |
| 括注 | 角色名或台词下面带括号的一行：声源、对谁说、从哪个词抢话；不写情绪 | — |
| 对照翻译 | 紧跟在一句台词下面的另一种语言的行；脚本不计入，导出时可去掉 | 字幕行 |
| 标准页 | `render_screenplay.py` 从剧本导出的页面：Courier 12 pt、标准页边距，可打印成 PDF | — |
| 制作参数 | 约束文件 `## 制作参数` 一节：英文语速、中文语速、单条生成上限；脚本据此估口播秒数，没配置就不估 | 写死在脚本里的 4 词/秒、30 s |

不用的写法：口语比喻（"债""欠什么""那一下"）、口语化的列名（"谁对谁""对方怎么接""挡住什么"）、"此刻"作列名或标签（改用"当前"）、散文段落、同一件事在几处各写一遍（写全一处，别处留指针）。
