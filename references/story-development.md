# 上游：讨论落稿、困境推演、前后场依赖、观众知情、生活研究

用法：处境卡、方向卡、节拍单阶段读（SKILL.md §2 第 1–3 步），改稿时发现根因在前场也读 §3。每节写触发、做法和交付；案例出处见 `sources.md`。

## 1. 讨论落稿

**触发**：用户贴来一段讨论记录、构思，或一串零散的改稿意见。

**做法**：逐条分四类，每条带原话：

| 类 | 是什么 | 去向 |
|---|---|---|
| 已决定 | 用户明确定下的走向、事实或改法 | 进处境卡和节拍 |
| 备选 | 提过、没定的走向；说得好但没采用的台词 | 备选区（方向卡的候选、批注里的备选台词），不进正文 |
| 未决 | 不定下来就写不了下一步的问题 | 处境卡的核心待决问题；只列真正卡住的 |
| 待核实 | 事实、职业细节、时间线 | 写明要谁核实；核实前按推断标注 |

**交付**：处境卡的入口栏按四类列出（`templates/situation-brief.md`），加上当前可写的场景走向和会阻止写作的未决问题。讨论过不等于已定设定（风骚律师：临时卡逐场深入后才变成措辞明确的正式卡）。

## 2. 在固定条件下推演困境

**触发**：下一集没有事件；人物轻易脱困；反转靠巧合。

**做法**：

1. 锁定条件：人物当前的目标、已知信息、可用资源、空间与时间的限制、不能改的事实。
2. 出办法。每条写：谁会想到，为什么愿意这样做，解决眼前的问题之后损伤了什么（代价落到关系上）。不用尚未建立的能力、巧合或突然出现的帮手解围。（绝命毒师：Hank 把两人堵在房车里，编剧室最后用一通假报 Marie 出事的电话把他引走；讨论中被否的办法，有的成了 Jesse 当场提出的想法。）
3. 核心事件可以是本集新发生的事，不必从伏笔里倒推；写成新事实提案，伏笔用来承接它的后果。只从伏笔推方向，容易一再回到老线索。
4. 每个候选写一行"关系与处境：起点 → 终点"。

**交付**：方向卡上的候选与后果（`templates/directions.md`）。被否的办法可以留作人物会尝试的失败行动，但不自动写进正文。不用吵得更凶、事故更大代替因果推进。

## 3. 前后场依赖：后场转折倒查前场

**触发**：一个后场转折写不可信；"这个人为什么会在这里""他怎么知道的"答不出。（第一头牛：初稿写到追赶时，导演追问追来的究竟是谁，于是扩写宅内的人物与活动，再回到前面把这些人提前安排进故事。）

**做法**：列出转折成立需要的人物、物件、知识和关系；逐项查哪些已经建立、在哪一场；缺的写最小补写——补在哪一场、最少建立什么、这段补写在那一场本身有什么作用（不让人物只为未来某一幕突然出现）。

**已采用或已拍的场**：只出影响清单、最小修改和代价，交用户定；已拍锁定的不动。不因为后场有了新主意就覆盖旧稿（SKILL.md §3 第 3 条）。

**交付**：受影响的场次和最小补写，不新建一张伏笔表。

## 4. 观众知情

**触发**：悬念不成立；观众跟不上；揭晓显得突然；人物知道了不该知道的事。

**做法**：在台账 B 节的关键节点上标：人物知道什么；观众知情、不知情还是误信；观众此刻在等哪个答案。查铺垫与兑现之间有没有可以追踪的联系；改动信息顺序时，连带核对后场。区分两种不知道：观众在期待一个答案（悬念），还是看不懂基本局面（困惑，要修）。

**交付**：最需要调整的几个信息节点和对应场次。不做覆盖每句台词的大表。

## 5. 生活研究

**触发**：陌生的职业、地域、年代或关系写得空。

**做法**：从将要发生的事件反推问题——当事人实际先做什么；谁能拒绝、拖延或结束这件事；彼此怎么称呼；哪些话大家都知道所以不说；说完一句话之后实际去做什么。优先找本人访谈、可核对的操作材料和用户提供的观察；必要时列一份访谈提纲交给用户。提取的是说话完成的事，不只是职业名词或口音（Fargo：推销戏来自 Ethan 买车的经历）。

每条材料标明：查实 / 个人观察 / 推断 / 虚构设计，并写出处。改编真实事件时，合并人物、压缩时间、调换顺序另列，不混进研究事实。生活观察不自动成为正典。

**交付**：少量能改变当前这场戏的细节、它影响的台词或动作、待核实项。不用百科式介绍代替创作。
