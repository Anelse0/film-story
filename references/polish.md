# 精修（Script Polish）：结构定了以后，按简报做一轮

用法：SKILL.md 第 5 步的精修；用户说"润色一下""精修""锁稿前再过一遍""对话太工整""像在念台词"时读。现成的精修类型在 §9，锁稿前的连续性核对在 §10。初稿和重写见 `scene-work.md`；对白怎么写、按反馈怎么改见 `dialogue.md`、`dialogue-patterns.md`；动作描写的约定见 `screenplay-format.md`。重写与精修的分界出处见 `sources.md`"阶段"。

## 1. 重写还是精修

| | 重写（Rewrite） | 精修（Polish） |
|---|---|---|
| 动的是 | 情节、故事线、人物之间的关系：这场发生什么、谁做了什么选择、谁知道什么 | 对白、动作描写、留白：这场读起来、听起来怎么样 |
| 怎么分 | 改完，节拍单要跟着改 | 改完，节拍单一个字不用动 |
| 用户的话 | "他不会这么做""这场没发生什么""两人在轮流解释" | "这句不自然""太满""没有喘气的地方""像在念说明""太工整，像在念台词""润色一下" |
| 做法 | `scene-work.md` §3–§6 | 本文件 |

拿不准时看第二行：这处改动要不要回头改节拍单。要，就是重写。

## 2. 流程：简报先行

1. **用户发起**，给意见和方向。结构还在动（场次、事件、动机、谁知道什么还有没处理的意见）时不做。
2. **写精修简报**（`templates/polish-brief.md`），交给用户，停。简报把这一轮要做的和不能碰的写在一处，用户改的是简报，不是改完的稿。
3. **用户确认后一轮做完。** 只做简报里写了的；做的时候另外发现的，记下来，不顺手改。
4. **交付**：新版剧本；简报里每场补上"改了什么"、验收逐条写结果；比稿（§7）。
5. **用户审过** → 状态改"精修 · 已采用"，也就是锁稿，可以交导演层。还有意见 → 按意见改这几处，不另起一轮。用户说"有条件锁稿" → 状态写"精修 · 有条件锁稿"，还差的条件记进简报，下一轮只做这些（§10）。

用户只说"精修一下"、没给意见：先通读、跑检查脚本，按 §3 起草简报交用户改，不动稿。精修是用户发起的一轮，做完就停，AI 不自己发起下一轮。用户点到的句子不受这个流程限制，任何阶段都直接改。

## 3. 简报里写什么

| 节 | 写什么 | 为什么要有 |
|---|---|---|
| 抬头 | 基于哪一版；这是一轮有针对性的精修，不是重写；目的 | 这一轮的边界先说死 |
| 这一轮的一条原则 | 类型（一般精修，或 §9 现成的类型）；一句话目标；它是什么、不是什么；本集已经做对的一处当参照；每处改动过的问题 | 一轮只追一件事，改动才有同一个标准 |
| 仍然有效的要求 | 本剧规则、节拍单已定的决定、这一集历次意见里还作数的，分格式、观众看到的、故事与正典、对白 | 防止这一轮把以前改好的改回去 |
| 锁定的台词 | 用户定过的句子，逐字，一句一行 | 脚本逐字核对，少一句不交付 |
| 人物声音 | 一人一条：他会怎样，不是怎样；两人之间怎样 | 声音的方向先对齐，再动句子 |
| 逐场 | 每场是基本不动、小改、重点还是局部重写；保留什么，改、删、考虑什么；重点场写明不动的情感结构 | 好的场先保下来；改动落到具体的场 |
| 指定改法 | 用户点名的句子：现在的句子 → 改成的句子（为什么），逐字照办 | 脚本核对都改了；原因留着，以后不会被改回去 |
| 这一轮取代了什么 | 原来的选择、出处、现在的方向；表里没有的照上一版 | 新意见和旧决定冲突时，点名哪条作废 |
| 结构已锁 | 指向节拍单；列出不新增的东西 | 不重开已经定了的 |
| 锁稿前的连续性核对 | 意图、正典、集内、呼应、后续、占位符（§10） | 最后一轮顺手把对不上的地方清掉 |
| 验收与交付 | 可以逐条核对的标准；交付物 | 做完对着查，不靠"感觉好多了" |

人物声音的写法举例：写"她的强势是不解释，不是嗓门大"，不写"她很强势"。两人之间的熟悉写成认得出的说话方式——自己的简称、小误会——不写成句句都懂。

## 4. 留和删：看作用，不看长短

- 不自动缩短，也不自动加长。
- 留下建立人物、关系、幽默、张力和说话节奏的；删掉重复的、解释的、填充的。
- 每处改动过两问：
  1. 这两个人会对彼此说这句吗，还是作者想让观众明白？
  2. 它有没有像人说话的余地，又没说得比这一刻需要的多？
- 好的场保留，不为了新鲜重写。改得少，可能正说明前面做得好。
- 有依据的直接表达（告白、道歉、承认）保留；把明白话改含糊不算精修（`dialogue-patterns.md`"不要误删的写法"）。

## 5. 呼吸感是什么，不是什么

用户说"太满""没有喘气的地方"时，要的不是更多台词，是台词里有更多活气。

| 是 | 不是 |
|---|---|
| 反应来自人物手上正在做的事 | 加一句台词，重复观众刚看到的事 |
| 回答来晚了、只答了一半，或者没来 | 加一句台词，解释潜台词或总结处境 |
| 话没说完，对方已经懂了 | 到处撒口头填充词 |
| 一句小拌嘴、一场不要紧的争执，显出两人多熟 | 在已经写完的对话上再加停顿和手势 |
| 只是舒服的沉默，不带别的意思 | 只为解释情节加的电话、道具、停顿 |

## 6. 不动什么，局部重写怎么登记

- 不动：场和场景标题的数量与顺序；每场谁说话；谁做了什么、结果怎样；人物的动机和选择；谁知道什么；锁定的台词。
- 用户点名要在这一轮里重写某一场的局部时，在简报"逐场"里登记成"局部重写"，写明三样：要让观众明白什么、保留什么、不许什么。用户给的示范台词是参考，不是必须照抄的措辞。
- 没登记的场，做的时候发现结构有问题：停在那一处，记进简报的结果栏，交回重写。不顺手改，因为顺手改的结构没有人核对过因果。
- 场与场的衔接也算结构：不为了接上下一场硬加一句理由，不为情节把人物挪来挪去。衔接别扭时记下来，不在精修里补一句台词了事。

## 7. 交付与验收

1. 剧本文件升一版，状态写"精修 · 进行中"。
2. 比稿：
   ```bash
   python3 scripts/compare_drafts.py <剧本.md> --rev <精修前的那一版> --brief <精修简报.md>
   ```
   - 锁定的台词要逐字都在；指定改法要都改了。
   - 表演线索前后的数只作参考：停顿、填充词成片增加，核对是不是在装真实。
   - 没登记的场，"结构"一行要是干净的。不干净说明这一轮越界了：改回去；确实该改的，记进简报交用户定。
   - 它列出的台词改动核对后贴进剧本头部的"本版改动"；动作段的变化一场并成一句。
3. 简报里每场补上结果，验收逐条写结果。可换的备选写进批注文件的"可换"组。
4. 另出一种语言的版本时（比如动作描写换一种语言、对白不变），两个版本的对白要逐句相同：`python3 scripts/compare_drafts.py <版本一.md> <版本二.md> --dialogue-only`。

精修前要有一个可比的旧版：剧本已提交就用 `--rev HEAD`；没提交过，先把当前文件另存一份到临时目录再动笔，不放进项目。

模型听不见声音。语气、读起来顺不顺口的判断标"模型分析"；拿不准的不替换，挂成备选交用户定（`dialogue.md` §7）。

## 8. 什么时候算完

简报里写了的都做了；验收逐条有结果；锁定的台词都在；没登记的场结构没变；用户审过。不要求每句都改过。

## 9. 现成的类型：表演驱动的对白精修（Performance-Driven Dialogue Pass）

简报"这一轮的一条原则"里写"表演驱动的对白精修"，本节的内容就都带上，不用重抄；简报里只写这一集特有的。

**什么时候用**：结构和情感都成立了，但对话像在念写好的台词——每个人都知道该说什么、什么时候接、怎么替对方把话说完。纸面上高效，演出来机械。用户的话："太工整""像在念台词""太像写出来的"。

**一条原则**：人物边活边说，不是停下手里的事来说台词。手上的事决定他注意到什么、什么时候回答、话说不说完、分给对方多少注意力。要的不是更多对白，是对白里有更自然的行为。

| 要的 | 不要的（成套地加就假） |
|---|---|
| 有时马上答，有时先把手上的事做完 | 填充对白、寒暄、重复的信息 |
| 答的是问题的实际意思，不是它的情感含义 | 口头填充词 |
| 两个很熟的人，有时没什么聪明话可说 | 多余的停顿、意味深长的对视、没说完的句子 |
| 一句要紧的话后面跟着平常的事，不是另一句要紧的话 | 每个来回都配一句俏皮话 |
| 不是每个情感时刻都要被接住、解释或说完 | 只为显得忙而加的小动作；装出来的尴尬 |

右栏的手法偶尔出现是自然的；成套地加，就和工整的台词一样假。真实感不是有瑕疵，是有可信的行为。

**五问**（每个来回过一遍；改动清单里写明对应哪一问）：

1. **动机**：他为什么现在开口——要沟通、逗对方、弄清楚、回避、分享，还是只是应一声？还是这句在这里只因为观众需要信息？
2. **手上的事**：他说话时在做什么？这件事有没有影响他什么时候答、注意力在哪、怎么措辞？把动作拿掉，这段对话会不会露出打磨过头的样子？
3. **关系**：这段对话换任何两个人都成立吗，还是带着这两个人的熟悉、过往和性格？
4. **节奏**：两人是不是总是立刻、完美地回答？每句话是不是都有一句设计好的对句？是不是太多来回落在包袱或小结论上？
5. **必要**：这处改动有没有带来人物、关系或戏剧上的东西？没有就不加。

目标不是把对话改长、改乱、改随意，是改可信。

**做法**：

- 重点场先锁情感结构：把这场的事写成几步，指到节拍单的拍，不动；只改说法和行为怎么走。必要的信息仍然要说清楚。
- 从本集已经做对的一处取参照，学它的原理，不复制它的形式，不为了多一处呼应再来一次。
- 人物不必一到要紧的话就停手，对方也不必每句都立刻、完美地接；但也不为了冲淡每句认真的话去加玩笑、打断或手势。
- 不同关系的对话节奏要分得开：合作多年的两个人和刚熟起来的两个人，不是一个说话节奏。
- 两人之间的熟悉从这些地方出来：认得出的习惯、就事论事的小逗、不用解释的反应、对彼此平常举动的自在、说话节拍偶尔对不上、看懂了却不说破。不必时时调情、处处有象征。
- 只做有理由的局部改动；不整场重写，不成片地加长对白。
- 只写人在干什么、什么时候答。表情、微表情、机位不进剧本，归导演层。

**脚本**：`check_dialogue.py` 每场报一行表演线索——停手、停顿、对视、填充词、没说完各几处，并列出停手的那几行；`compare_drafts.py` 报这几个数前后的变化。只数不判：停手多，核对是不是一到要紧的话就停下手里的事；这一轮之后停顿和填充词成片增加，核对是不是在装真实。

## 10. 锁稿前的连续性核对

用户说"有条件锁稿"时，结构和叙事不再动，还差的条件写在简报里；条件都过了才是"精修 · 已采用"。锁稿前逐条核对，结果写进简报：

| 核对 | 看什么 |
|---|---|
| 意图 | 人物的意图有没有歧义：想做和已经决定做，分不分得开 |
| 正典 | 提到的往事和细节，和以前的集、已拍的内容对不对得上（查台账） |
| 集内 | 前后场有没有互相矛盾 |
| 呼应 | 前后呼应的声音、物件，在成片里认不认得出；要制作配合的，写进交导演层的条件 |
| 后续 | 这一集定下的条件，和后面几集的计划冲不冲突 |
| 占位符 | 正文里的占位符和待定标记清零（`check_constraints.py` 会列出来） |
