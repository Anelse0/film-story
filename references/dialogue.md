# 对白：从两个人的交往写出来

用法：写一场的对白，或用户说"这句不像他会说的""太普通 / 没魅力 / 不够 hook""每个人都在讲道理"时读。SKILL.md §4 的三测在写完之后用；本文件讲怎样写出来、怎样按反馈改。四种固定失误和不要误删的写法见 `dialogue-patterns.md`；案例出处见 `sources.md`。

## 1. 先写两个人怎样相处，再定句子

先看：谁面对谁，各自知道什么，刚发生了什么，这一次开口在争取、分享、回避还是办成一件事。人物可能同时想靠近又怕承担，想结束又不愿伤人；也可能只是坦率地提供信息。复杂来自具体处境，不预先给每句台词安排秘密。

亲密对话里的赞同、共同回忆和顺利的接话同样可以鲜活。"自然"也不等于松散、即兴或没有事件：自然的交流可以完全写定（迷失东京的初见与彻夜长谈主要按剧本拍）。

## 2. 一轮交流怎样写：交替代入

- 第一句从人物眼前注意到的东西、一个实际的请求、分享或动作开始。暂时放下作者想让他传达的结论。
- 换到听的人那里：他最在意其中哪一点，会不会听错，想不想谈？写出他的回应，再让前一个人面对这个新事实继续。不要求每一句都有明显的刺激和反应。
- 不先替两人各写完立场陈述再交错排列，那样写出来就是辩论式（`dialogue-patterns.md` 第 1 条）。
- 断句、改口、说不完从处境里长出来，不预先给所有角色加断句、抢话和答非所问。（海边的曼彻斯特：Lonergan 写街头重逢时在脑中分饰两角，她想接近，他想脱身又不愿伤她。这种牵制让完整的拒绝说不出口——这一句是本 skill 的推断，不是他的原话。）
- 对话没有继续下去的理由时先不润色：查两人为什么在一起，现在适不适合谈这件事，开口之后对方能做什么。关系结论占满了整场 → 重做交往方式（Walking and Talking 的改写，出处未复核）；对话本身就在办事 → 保留说话，重写触发与接收（`scene-work.md` §4）。

## 3. 人物声音从已采用的台词取证据

- 看具体的选择：他先注意事实还是关系、价格还是面子；怎样提要求、承认不懂、拒绝、开玩笑；先解释流程还是先安抚对方；被识破之后换理由、承认，还是继续倚仗权限。句法、称呼、词汇和节奏跟着这些选择走。
- 证据记在台账可选的 G 节"声线依据"（`templates/ledger.md`）：人物、对谁、处境、已采用原句（场·版本）、观察到的做法、暂定或已确认。样本少写"暂定"；一场的台词只说明这一场，不马上变成永久规则；后来的采用稿可以修正早先的判断。
- 同一个人对不同的人换说法，不是声音不一致。口音和口头禅代替不了声音，声音首先来自他关注什么、用什么办法办事（Fargo 的推销戏：推托、给台阶、转移责任、用职业权限）。
- 说话不顺也可以是声音：准备好的话失效、以为对方听懂了、补救失败、对方不配合（查理和巧克力工厂的修订页）。
- 声音不等于强度：一句话的音量和强度由这场推到了哪里决定，不从人物小传套（SKILL.md 第 0 步）。

## 4. 按反馈改对白

| 用户的话 | 做什么 | 改到哪里 |
|---|---|---|
| "太书面" | 保留说话行为，改词序、称呼、指代和节奏；先核对这个人是不是本来就说话正式 | 可以直接替换的台词和必要的接续 |
| "人物都一个声音" | 比较他们在同一处境下注意什么、觉得什么不用解释、被拒绝时怎么办，再改表达 | 有人物依据的关键来回，不堆口头禅 |
| "每个人都在讲道理" | 找出谁在回答作者、谁根本没接到上一句；从眼前的刺激重写回应 | 写到新的回应产生实际后果 |
| "配角只是捧哏" | 让听者从自己的经验、误解、关切或手上的事回应，不复述主角 | 不强求台词等长，改到听者成为场里的人 |
| "解释太多" | 查说的人为什么此刻讲、听的人为什么需要听、信息之后怎样被使用 | 不起作用的解释删改；劝诱、辩解、试探里的长谈可以保留 |
| "不够有感情" / "太直白" | 查前面的行动与关系能不能撑住这次表达；缺的是触发，就先补触发 | 保住有效的告白、道歉、承认；改成谜语不算改好 |
| "不够自然" | 找具体问题：没有开口的理由、回应不可信、动作过大，还是句子确实难说 | 改相应的层面；不统一添加停顿、粗口、跑题 |
| "太普通" / "没魅力" / "不够 hook" | 查三件事：这句只有这个人会这么说吗；碰到两人之间的事了吗；有没有给对方一个要接招的东西（邀请、挑衅、留着不答）。缺哪件补哪件，不靠金句，也不靠把话说漂亮 | 关键的一来一回，连对方接招的那句一起写；日常琐事只在显出这个人、或碰到两人之间的事时留下 |
| "他一直在问" | 问句把主动权交给对方。一部分改成断言、拆穿、嘴硬或动作；留下的问句要有回答之外的作用（试探、拖延、挑衅） | 这个人在本场的台词；脚本对"某人问句过半"会给线索 |

**例："我想你"本身不是问题。**

> A：我想你。
> B：你又这么说。
> A：那你让我怎么办？

施压来自最后一句：它把解决的责任推给了对方。保留直接的表达，只改最后一句的行为：

> A：我想你。
> B：你又这么说。
> A：嗯，又说了。

用户还要保留"再见一面"的诉求时，改成一个允许被拒绝的请求，不靠删掉诉求制造表面上的克制：

> A：我想你。
> B：你又这么说。
> A：周六我在老地方。你不来也行。

## 5. 听者在场

- 回应可以是接住一个词、迟一拍才明白、拒绝回答、想起自己的事，也可以没有明显变化；重要的地方要看得出他为什么这样接下去。
- 让听者有自己的经验和选择，不是平均分配台词；审讯、汇报、第一次倾诉可以明显不对称。（Sideways：后来的稿子让 Maya 也有了她自己的那一段。）
- 沉默的人在听什么、怎样承受：先给他反应的机会，再决定要不要补台词。站还是坐、服装上的动作、调度交给导演层。（婚姻故事：法庭戏里夫妻通过听律师发言作反应。）

## 6. 备选连着反应写

- 同一个目的可以换办法：直接请求、借事务试探、用玩笑留退路。替换关键句后，至少接写它实际改变的那句回应，才看得出新办法有没有用。
- 三条同义句不是三个方向。同一句"我没事"可能是阻止追问、维持体面，也可能确实只是在提供信息，由上下文决定。
- 备选挂在批注块的原句下面（SKILL.md §4）。

## 7. 可说性与关系效果分开查

- 文本检查（三测、脚本）能发现指代不清、不起作用的重复、接续断裂。
- 人物为什么不肯说、听者为什么没接住、行为尺度是否过大，真人读稿更容易暴露。模型不报告"读起来"的效果，也不虚构读稿结果（`scene-work.md` §7）。
- 计时分三种：对白朗读、带动作和停顿的排练、成片。脚本的秒数只是第一种的粗估。（社交网络：Fincher 请 Sorkin 照写作时听到的节奏读全稿，逐场计时，再在排练里调速度。）
- 模型的文本分析和真实读稿记录分别注明来源。
